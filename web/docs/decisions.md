# Web Decisions (W-xxx)

Implementation-level decisions for `web/`. Cross-cutting decisions are in `../../docs/decisions.md` (read-only for this project).

| ID | Date | Decision | Rationale | Status |
|---|---|---|---|---|
| W-001 | 2026-09-29 | Pin `vite@^6` together with `vitest@^3` (instead of `vite@6` + `vitest@2`). | `vitest@2` bundles its own `vite@5`, so two copies of Vite's types existed and `tsc -b` failed with incompatible `Plugin` types in `vite.config.ts`. One deduped Vite fixes it. | Accepted |
| W-002 | 2026-09-29 | A local, gitignored `.env` (`VITE_USE_MOCKS=true`) ships alongside the committed `.env.example`. | `npm run dev` must work on mocks out of the box (T3 "done when"), and `.env` is never committed or baked into the image. | Accepted |
| W-003 | 2026-09-29 | One strict root `tsconfig.json` (no `tsconfig.app.json`/`tsconfig.node.json` project references) while keeping the `tsc -b && vite build` script. | `tsc -b` only needs `composite` projects when there are references; a single project keeps the config readable and still type-checks `src/` and `vite.config.ts`. | Accepted |
| W-004 | 2026-09-29 | `@/*` path alias → `src/*`, declared in both `tsconfig.json` (`paths`) and `vite.config.ts` (`resolve.alias`). | Keeps imports readable in a deep component tree; the two declarations are the standard Vite setup. | Accepted |
| W-005 | 2026-09-29 | No git repository could be created or committed to because the workspace has no `.git` (and the repository root sits above `web/`, outside this project's boundary). | Creating a nested repo inside `web/` would corrupt the parent repository's ownership model. Progress is tracked in `docs/progress.md` instead. | Superseded by D-027 |
| W-006 | 2026-09-29 | `ApiError` keeps the whole parsed JSON body (`status`, `code`, `message`, `body`) plus an `agentErrorBody` accessor for the 502 case; a timeout or transport failure throws `ApiError {status: 0, code: 'NETWORK_ERROR'}`. | The 502 `AGENT_ERROR` body carries `patient_message`/`agent_message`, so the chat needs the raw body, not just the message string. | Accepted |
| W-007 | 2026-09-29 | `login()` passes `allowUnauthorized`, so a 401 from `POST /auth/login` (wrong credentials) neither clears the stored token nor redirects. | The contract treats a login 401 as "wrong credentials", not "session expired"; wiping an existing session on a failed re-login would be wrong. | Accepted |
| W-008 | 2026-09-29 | The CSV export is fetched through `apiFetchRaw` and downloaded from a Blob (with `adminExportUrl()` kept as a pure URL builder). | The endpoint requires the `Authorization` header, so a plain `<a href>` cannot be used. | Accepted |
| W-009 | 2026-09-29 | MSW handlers are declared with the wildcard origin (`*/api/v1/...`). | One handler set then serves both the browser worker (same-origin requests) and `msw/node` in tests, without an origin constant that could drift. | Accepted |
| W-010 | 2026-09-29 | The mock turn delay is configurable (`setMockTurnDelayMs`): 3–6 s in the browser, 0 in tests. | The contract asks for a 3–6 s delay for realism, but a 25-case handler suite must not take minutes. | Accepted |
| W-011 | 2026-09-29 | Test-only fetch bridge: under Vitest's jsdom environment the harness wraps `globalThis.fetch` and drops `RequestInit.signal`. | Node's `fetch` (undici) rejects an `AbortSignal` from another realm, and Vitest's jsdom supply a different `AbortController`; MSW sits on Node's `fetch`, so every request carrying a signal failed before reaching a handler. Cancellation is not exercised by those tests (mock delay 0); the timeout itself is unit-tested with a stubbed `fetch`. | Accepted |
| W-012 | 2026-09-29 | All eight mock agents have `description: null` (the contract allows `null`). | The card renders the description when present, but inventing Persian marketing copy for a blind doctor risks hinting at the model or architecture. | Accepted |
| W-013 | 2026-09-29 | Every label map is typed as an exhaustive `Record<Enum, …>` and `@/api/types` exports the runtime enum lists used by the label tests. | A missing or misspelled enum value becomes a compile-time error, and the tests can iterate the contract enums instead of a hand-written list. | Accepted |
| W-014 | 2026-09-29 | `src/i18n/uiText.ts` is the only place static Persian copy lives; strings with no `UI_SPEC` source are flagged in that file's header. | Keeps `UI_SPEC` texts verbatim and makes the handful of invented strings (form section headings, comparison-select label, backstage enum labels, reload toast) auditable. | Accepted |
| W-015 | 2026-09-29 | `clearStoredAuth()` dispatches a `triage-lab:auth-cleared` window event, and `AuthProvider` listens to it; the query client is cleared at the same time. | A 401 must drop the in-memory session, not just localStorage; centralising it also makes `logout()` a one-liner. | Accepted |
| W-016 | 2026-09-29 | The router opts into the React Router v7 future flags (`v7_startTransition`, `v7_relativeSplatPath`). | Removes the deprecation warnings from the dev console and the test output without changing behaviour. | Accepted |
| W-017 | 2026-09-29 | The backstage panel renders one item per `BackstageTurn` in the order returned, titled with the text of the agent message the turn belongs to, and every field the contract allows is rendered by one generic key/value renderer (nested arrays and objects inside a collapsible «پرونده بالینی»). No branch on architecture. | `AGENTS.md` forbids branching on architecture, and `BackstageTurn` fields are all optional; a generic renderer shows whatever a given architecture sends and survives new fields without a code change. | Accepted |
| W-018 | 2026-09-29 | `GET /sessions` (history tabs) and `GET /admin/metrics` (group-by switch) use `placeholderData: keepPreviousData`. | Both switches are refetches of the same table shape, so keeping the previous rows avoids a skeleton flash that reads as a page reload. | Accepted |
| W-019 | 2026-09-29 | The CSV test helper `stubDownloads()` replaces `URL.createObjectURL`/`revokeObjectURL` on a subclass of the real `URL` (`class StubURL extends URL {}`), never on the global `URL` object. | MSW and React Router construct `URL`s internally; assigning a plain stub over the global broke both libraries' request/router plumbing. | Accepted |
| W-020 | 2026-09-29 | `adminReloadToast(loaded, enabled)` takes pre-formatted Persian-digit strings; the page calls `faNumber` before interpolating. | `uiText.ts` owns the Persian template and must stay free of formatting logic, and keeping the arguments as strings makes the assertion in the test read as the exact UI text. | Accepted |
| W-021 | 2026-09-29 | Every evaluation control is wrapped in an element with `id="field-<key>"`, and the first invalid field is brought into view with `scrollIntoView({ block: 'center' })`. | Radios, checkboxes, selects and textareas need one stable anchor for both the per-field error lookup and the scroll target; the guard for a missing `scrollIntoView` keeps jsdom (which has none) working. | Accepted |
| W-022 | 2026-09-29 | The admin session detail reuses `SessionContent` in read-only mode with the reveal forced on and all users' feedback shown. | One rendering path for chat, result, backstage and evaluation means the admin view cannot drift from the doctor view; admins are not blind by design (§3.6), so the reveal is shown there. | Accepted |
| W-023 | 2026-09-29 | `public/mockServiceWorker.js` is now committed (generated with `msw init public/ --save`, recorded as `msw.workerDirectory` in `package.json`), and `main.tsx` wraps `worker.start()` in a `try/catch` that logs and renders the app anyway. | Found by the 375 px browser QA: with no `public/` directory the worker URL fell through to the SPA fallback, was served as `text/html`, the registration failed with an unsupported-MIME error, `enableMocking()` rejected, and the app showed a **blank page**. Every jsdom test missed it because they run `msw/node` and never touch the browser worker. | Accepted |
| W-024 | 2026-09-29 | nginx resolves the API upstream per request: `resolver 127.0.0.11 valid=10s ipv6=off;` plus `set $api_upstream ${API_UPSTREAM};` and `proxy_pass $api_upstream;`. | With a literal `proxy_pass http://backend:8000` nginx aborts at start-up (`host not found in upstream "backend"`) whenever the backend is not resolvable yet — including a plain `docker run` with no backend, and the race at compose start-up. Verified: the container boots standalone, returns 502 per request while the backend is absent, and 200 once `backend` resolves. | Accepted |
| W-025 | 2026-09-29 | The upstream host is configurable at run time through `API_UPSTREAM` (image default `http://backend:8000`), substituted by the nginx entrypoint via a `/etc/nginx/templates/` template with `NGINX_ENVSUBST_FILTER=^API_UPSTREAM$`. | A deploy must be able to point the same image at another host without a rebuild; the filter restricts substitution to that one variable so nginx's own `$uri`, `$host`, … survive untouched. | Accepted |
| W-026 | 2026-09-29 | The image build deletes `dist/mockServiceWorker.js` after `vite build`. | `public/` is copied verbatim and the image is built with `VITE_USE_MOCKS=false`, so shipping the worker would only add dead bytes and a misleading mock surface to a production artifact. | Accepted |
| W-027 | 2026-09-29 | The invented Persian strings added in T9–T11 (the KPI and comments block headings, the comparison-select label, the agent-reload toast) are marked `invented` in `uiText.ts`, extending W-014. | Keeps the “verbatim `UI_SPEC` text or explicitly flagged invention” rule auditable as new blocks were built. | Accepted |
| W-028 | 2026-09-30 | `ApiErrorCode` (a union of every `API_CONTRACT §1` code) and the runtime list `API_ERROR_CODES` are added; `ApiErrorBody.error.code` is typed with it. `ApiError.code` stays `string` so the client's `HTTP_<status>` fallback still fits. | The contract error codes had no type at all; v1.1 adds `METHOD_NOT_ALLOWED` and `INTERNAL_ERROR`, and the error-handling tests iterate a runtime list (mirrors W-013). | Accepted |
| W-029 | 2026-09-30 | The MSW worker is kept out of production builds two ways: `vite.config.ts` aliases `@/mocks/browser` to `src/mocks/browser.stub.ts` and sets `build.copyPublicDir` to `VITE_USE_MOCKS === 'true'`. `scripts/check-no-msw.mjs` proves it. | Fixes phase-1 known issue 1 (the dead `browser-*.js` chunk) and stops `public/mockServiceWorker.js` from reaching `dist/`. `public/` holds nothing else, so gating the copy loses nothing; the dev server still serves `public/` with mocks on. | Accepted |
