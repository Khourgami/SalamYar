# Backend Decisions (B-xxx)

Implementation-level decisions for `backend/`. Cross-cutting decisions are in `../../docs/decisions.md` (read-only for this project).

| ID | Date | Decision | Rationale | Status |
|---|---|---|---|---|
| B-001 | 2026-09-29 | The workspace has no git repository. A repository is initialized **inside `backend/`** (with its own `.gitignore`) so the required `backend:` commits can be made without touching files outside `backend/`. When the root repository is created, fold this history in with `git subtree add --prefix=backend <path-to-backend-repo> main` (or `git filter-repo --to-subdirectory-filter backend`), or simply delete `backend/.git`. | The folder boundary forbids creating `../.git`; a nested repo keeps history and is trivially removable. | Superseded by D-027 |
| B-002 | 2026-09-30 | Pin `bcrypt>=4.0,<4.1` next to `passlib[bcrypt]`. | passlib 1.7.4 is unmaintained and breaks with bcrypt ≥4.1 (missing `__about__`) and ≥5 (72-byte ValueError during its self-test). 4.0.1 verified working. | Accepted |
| B-003 | 2026-09-30 | HTTP 405 responses use code `METHOD_NOT_ALLOWED` (still in the `{error:{code,message}}` shape). Other unmapped 4xx fall back to `VALIDATION_ERROR`. | The contract lists no code for 405; inventing a clearly named one is less misleading than reusing an unrelated code. | Accepted |
| B-004 | 2026-09-30 | Schema validators: `TurnDecision.message_to_patient` is enforced strictly both ways (non-empty for ask/clarify, empty for conclude). `SimpleTurn` enforces non-empty only for `ask`; on `conclude` the message may be non-empty (AGENT_SPEC §3 says it holds the final advice). `SimpleTurn.assessment` must be null on `ask` and present on `conclude` ("present iff"). | AGENT_SPEC §3 states "iff", but its own `SimpleTurn` comment requires a non-empty message on conclude; the comment is the more specific rule. The simple agent's patient-facing final text comes from `assessment.patient_message` anyway. | Accepted |
| B-005 | 2026-09-30 | G4 pre-validation hook is a `mode="wrap"` model validator on `AssessmentResult` that maps an unknown (or non-string) `specialty_primary`/non-null `specialty_secondary` to `general_practice` and sets a private attribute; the guard reads it via `AssessmentResult.specialty_invalid` and adds flag `specialty_invalid`. A missing specialty key still fails validation. | Runs on the raw JSON for every validation path (top-level and nested in `SimpleTurn`) without touching other fields. | Accepted |
| B-006 | 2026-09-30 | Prompt files are extracted byte-for-byte from the fenced blocks in AGENT_SPEC; the loader drops the single trailing newline. A test re-extracts the blocks from `docs/AGENT_SPEC.md` and compares, so spec edits that are not copied fail the suite. | Guarantees the "verbatim" rule mechanically. | Accepted |
| B-007 | 2026-09-30 | json_runner: transport failures (`LLMError`, already retried once by the client) are traced as a failed attempt and re-raised, not repaired. The repair request is a copy of the original with the failed `assistant` output and the rendered `repair` user message appended; it is traced with purpose `repair`, attempt 2. | Repair only makes sense for bad output; an unreachable provider is reported to the patient as `ERROR_FA` (502) so the evaluator can resend. | Accepted |
| B-008 | 2026-09-30 | Guard coverage is verified with `uv run pytest tests/test_guard.py --cov=app.agents.guard --cov-branch --cov-fail-under=100` (module form). The path form `--cov=app/agents/guard` from the phase prompt reports 0% because coverage.py only accepts packages or directories as sources, not a single file path without `.py`. | Same check, working syntax; `guard.py` stays a module as in the architecture layout. | Accepted |
| B-009 | 2026-09-30 | Guard G2 is evaluated on the triage level **after** G1. "with G1 off" is read as "G1 did not escalate": `high_prob_nonurgent` fires for SELF_CARE/ROUTINE_DAYS with p ≥ 0.10 when the floor is disabled or p is below the threshold. G3 treats sums within 1e-9 of 1.0 as not exceeding 1. G1 decides the final text: when it fires, the text is `EMERGENCY_TEMPLATE_FA + "\n\n" + DISCLAIMER_FA`, and `patient_message` is also set to the template. | After escalation the level is EMERGENCY_NOW, so a non-urgent flag can never apply; the epsilon avoids float noise flagging 0.7+0.2+0.1. | Accepted |
| B-010 | 2026-09-30 | `AgentOptions`/`AgentConfig` live in `app/agents/config.py` (shared by the guard, registry, and architectures). `AgentConfig.effective_temperature` returns `None` when `send_temperature` is false; the reveal reports this effective value. | Avoids an import cycle between guard and registry; one place defines what is actually sent. | Accepted |
| B-011 | 2026-09-30 | `TurnOutcome` gains `raw_assessment` (pre-guard) next to the guarded `assessment`; `force_conclude` takes `end_reason`; `SessionContext` also carries `previous_hypotheses` and a `save_clinical_state` callback (architecture B persists the new state right after the turn call, before any assessment call). | The service must store `raw_result_json` and needs the forced end reason; persisting via a callback keeps architectures DB-free while honoring "always persist the new clinical_state". | Accepted |
| B-012 | 2026-09-30 | The max-questions cap is enforced only in the service layer (checked before `next_turn`, and a question returned at the cap is discarded in favor of `force_conclude("max_questions")`), not inside the architectures. | The phase prompt specifies the architectures without an internal cap and the service check makes an architecture-level check unreachable; one enforcement point keeps `end_reason` correct. | Accepted |
| B-013 | 2026-09-30 | Trace purposes: architecture A `next_turn` → `turn`; A `force_conclude` → `assessment`; B turn call → `turn`, B assessment call → `assessment`; repair attempts → `repair`. With `output_mode: json_schema` the `response_format` carries `{name: <Model>, schema: model_json_schema(), strict: true}`. | A forced conclusion for A is the final assessment call, so it is labeled like B's; keeps per-purpose metrics comparable. | Accepted |
| B-014 | 2026-09-30 | Registry: agents removed from `agents.yaml` are kept in the `agents` table with `enabled=false` (sessions reference them by FK). Agent ids must be lowercase slugs; unknown keys and unknown `prompt_version` directories fail validation. | No deletions keeps history intact; strict validation fails fast on typos. | Accepted |
| B-015 | 2026-09-30 | Sessions keep the merged agent config in `agent_snapshot_json` and every turn runs from that snapshot (not the live registry), so a reload never changes a running session. `SessionSummary.agent` (display name/description) also comes from the snapshot. | Evaluations must describe exactly the agent that produced the conversation. | Accepted |
| B-016 | 2026-09-30 | Turn processing: the lock is taken with a committed conditional UPDATE and released in `finally` (also after unexpected errors). `llm_calls` rows are inserted (and committed) per attempt with `message_id=null` and linked to the resulting agent message (question/result/error) once it exists. Agent `error` messages also get `latency_ms` (wall time until failure); they are excluded from latency stats. `total_cost_usd` is null when no call reported a cost. The defensive "question beyond the cap → force_conclude" branch is kept but is unreachable because the cap is checked first. | No DB transaction is held across the LLM await; every trace survives failures; linking makes each call attributable to the message it produced. | Accepted |
| B-017 | 2026-09-30 | `ResultCard.stats.duration_seconds` is a float rounded to ms precision; `mean_turn_latency_ms` is a float rounded to 0.1 ms. `GET /sessions` uses `limit` 1–500 (default 50) and orders newest first. Evaluator scores and safety flags use strict types (a JSON `3.0` or `"3"` is rejected). | The contract types these as `number`; strictness prevents silent coercion of form data. | Accepted |
| B-018 | 2026-09-30 | Dev tooling: `app/llm/demo.py` (`DemoLLM`, deterministic valid JSON for all prompts) and `uv run python -m app.dev_server` (real app + DemoLLM, no OpenRouter). Not used by the production entry point. | Needed for the "manual run with FakeLLM via /docs" check and lets the web coder integrate (M2) without API cost. | Accepted |
| B-019 | 2026-09-30 | Feedback and evaluation are owner-only (admins get 403 on other users' sessions). Feedback check order: unknown message 404 → not owner 403 → wrong kind (greeting/patient/error) 400 → evaluated 409 `EVALUATION_LOCKED`. `DELETE` of non-existent feedback is an idempotent 204. `FeedbackRequest.note` may be omitted (defaults to null). | The phase prompt says "in a session the caller owns"; evaluations are the evaluator's own verdict. Idempotent delete simplifies client retries. | Accepted |
| B-020 | 2026-09-30 | `EvaluationInput` is validated strictly: every key in the contract is required (nullable ones may be `null` but not missing, including `comparison`), unknown keys are rejected, and body validation (400) runs before the state checks (409). An invalid comparison target (missing, same session, other user, not completed) → 400 `VALIDATION_ERROR`. | Mirrors the contract types exactly, so web/backend drift surfaces immediately. | Accepted |
| B-021 | 2026-09-30 | Metrics interpretation: triage rates (exact/under/over) use evaluated sessions where neither verdict nor final level is INSUFFICIENT_INFO; `undertriage_emergency_rate` uses the subset with verdict EMERGENCY_NOW. `specialty_match_rate` uses **all** evaluated sessions (INSUFFICIENT_INFO does not affect specialty). `insufficient_info_count` counts completed sessions whose final level is INSUFFICIENT_INFO. `mean_questions` and `mean_cost_usd` average over completed sessions (cost: those with a non-null total). Latency percentiles use all agent question/result messages of the group. Groups: every key with sessions plus every enabled agent (or its architecture/model), sorted by key. Grouping uses the session snapshot (architecture/model at session start); agent rows take label/architecture/model from the `agents` table. | PRD §9 excludes INSUFFICIENT_INFO only from the under/over-triage calculations; the phase prompt's "rates" rule is applied to the triage rates. Snapshot grouping attributes each session to the config that actually ran. | Accepted |
| B-022 | 2026-09-30 | CSV export: columns are exactly the table columns in model order, rows ordered by `created_at` (`updated_at` for feedback); null → empty cell, booleans → `true`/`false`, datetimes → ISO-8601, JSON columns stay JSON strings. Unknown table → 404. The `users` table is not exportable (not in the contract list). | One row per DB row, lossless, readable in Excel (BOM). | Accepted |
| B-023 | 2026-09-30 | smoke-test semantics: agents are selected by `--agent` (even if disabled) or else all enabled agents (plus disabled with `--include-disabled`). If a scripted turn already returns a result, later steps are skipped (`-`) and the conclusion counts as OK. Exit codes: 0 all OK, 1 any agent failed or a model is missing, 2 usage/config error or `/models` unreachable. Architecture B carries `previous_hypotheses` between the scripted turns as the service does. The CLI forces UTF-8 stdout/stderr (Windows consoles otherwise fail on Persian). | Matches the phase prompt table columns and makes the command usable in CI and on Windows. | Accepted |
| B-024 | 2026-09-30 | A second `POST /sessions/{id}/evaluation` returns 409 `EVALUATION_LOCKED` (message unchanged: "Session already evaluated"); check order unchanged (404 → 403 → body 400 → `SESSION_NOT_COMPLETED` → `EVALUATION_LOCKED` → comparison 400). B-003 (405) and the 500 handler are now contract codes (D-019); no code change needed. | Implements D-018/D-019 (contract v1.1). | Accepted |
| B-025 | 2026-09-30 | Audit for D-020: feedback and evaluation were already owner-only (B-019); `GET /sessions/{id}`, `POST /messages` and `POST /finish` allowed admins, so `load_accessible` (owner or admin) was replaced by `load_owned` (owner only, 404 before 403). `GET /sessions` was already filtered to the caller. Both lists now order by `created_at` desc, then `id` desc. An admin viewing **their own** session through `GET /sessions/{id}` still gets `reveal` (contract: "present iff evaluated (or admin)"). | Implements D-020 with the smallest change; the reveal rule is unchanged because the contract still names admins. | Accepted |
